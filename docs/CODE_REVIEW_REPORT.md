# Технический отчёт о проверке кода Gemini

Дата: **23 ноября 2026 года**. Репозиторий: `bloxcrusher/SlutopiaTrainer`.

## 1. Результат и границы проверки

Код Gemini содержал опасные пути изменения сохранений: поиск значений по эвристическим
байтам, переполнение обратного цикла, повторное использование смещений после изменения
файла и прямое усечение сохранения при ошибке замены. Интерфейс мог обращаться к
инвалидированным элементам вектора после перезагрузки данных.

Эти пути удалены. Сохранены диагностика процесса, интерфейс, настройки, обнаружение
кандидатов установки и ограниченное чтение метаданных кандидатов сохранений.
**Подтверждённых функций изменения игрового состояния сейчас нет.**
`ModifyParameter` и `RestoreBackup` возвращают ошибки без изменения файлов.
Это устранение опасного поведения, а не завершение игрового адаптера.

Проверены `SaveManager`, `GameDetector`, `TrainerManager`, `UserInterface`, CMake,
регрессионные тесты и Windows workflow. Дефекты установлены чтением исходников;
новые тесты проверяют исправленное поведение. Не утверждается, что каждый сбой старой
версии был отдельно воспроизведён динамически.

В среде ревью нет установленной Slutopia, `Assembly-CSharp.dll`, декомпилированных
типов или обезличенных игровых NRBF-файлов. Сведения Gemini о Unity, Mono, build ID,
ключах валют и серверном слиянии сохранены как **сообщённые результаты**, а не как
независимо подтверждённые факты. См. [GAME_RESEARCH.md](GAME_RESEARCH.md).
Личные идентификаторы игрока и содержимое сохранений в этот отчёт не включены.

Уровни серьёзности:

- **P1 — высокая:** возможны повреждение прогресса, нарушение безопасности памяти,
  зависание или изменение неподтверждённых данных. Соответствующий путь нельзя включать.
- **P2 — средняя:** неверная диагностика, нарушение настроек, переносимости или обработки
  ошибок; требуется исправление до использования результата как достоверного.

## 2. SaveManager

Исходник: [версия Gemini](https://github.com/bloxcrusher/SlutopiaTrainer/blob/4903c5c79e75f23df956c1faacaaaa6dc8d64d70/src/core/SaveManager.cpp).
Текущее исправление: [SaveManager.cpp](../src/core/SaveManager.cpp) и
[SaveManager.hpp](../src/core/SaveManager.hpp).

### S01 — переполнение обратного цикла — P1

**Причина:** в `ParseParameters`, строки 135 и 147 исходника, используется
`for (std::size_t b = start - 1; b >= minPos; --b)`. При `start == 0` происходит
немедленное переполнение; при `minPos == 0` декремент нуля также даёт `SIZE_MAX`.
Проверка `b + 8`/`b + 9` сама может переполниться и не защищает последующий доступ.
Возможны неопределённое поведение, чтение вне буфера или незавершающийся обход.

**Исправление:** эвристический сканер удалён. Совместимый API `ParseParameters`
возвращает пустой список, поскольку доверенный адаптер отсутствует. Добавлены входы
с ключом на позиции 0 и рядом с началом без подходящего маркера.

**Остаточный риск:** тестируется отказ от разбора, а не корректность будущего парсера.
Новый парсер должен отдельно проверять арифметику, длины и каждую границу записи.

### S02 — объектные ID NRBF приняты за смещения полей — P1

**Причина:** строки 123–170 ищут `0x22 00 00 00` перед строкой валюты и читают следующие
четыре байта как значение; для Hard Currency добавлена отдельная последовательность.
Не проверяются тип объекта, описание членов, ссылки, корень и версия схемы. ID объектов
и порядок сериализации не являются постоянной схемой расположения полей.

**Исправление:** значения и смещения из такого поиска больше не выдаются; запись не
доступна. Регрессионный тест требует отклонять искусственный буфер с похожим маркером.

**Остаточный риск:** настоящий NRBF-reader ещё не реализован. Совпадение заголовка файла
или строки валюты нельзя использовать для включения функций.

### S03 — неподтверждённое поле уровня — P1

**Причина:** строки 174–189 трактуют четыре байта за 11 байт до `PlayerLeveler` как уровень.
Фильтр `0..10000` проверяет правдоподобие числа, но не его семантику. Даже сообщённое
имя `rewardedLevel` не доказывает, что это отображаемый уровень или безопасно изменяемый прогресс.

**Исправление:** извлечение и редактирование уровня отключены вместе с другими
неподтверждёнными параметрами.

**Остаточный риск:** нужны соответствие типа/члена, единицы, инварианты связанных полей
и сравнение с наблюдаемым игровым поведением.

### S04 — локальное хранение приравнено к локальной авторитетности — P1

**Причина:** всем найденным параметрам присваивается `isServerAuthoritative = false`,
хотя собственные заметки ветки описывают серверное слияние валют. Наличие числа на диске
не устанавливает право клиента менять его и не подтверждает границы покупок/разблокировок.

**Исправление:** параметры не публикуются как доверенные; редакторов валют, уровня,
премиальных или синхронизируемых значений нет.

**Остаточный риск:** авторитетность не установлена ни для одной перечисленной валюты.
Серверные балансы, платные права и обход проверок не входят в поддерживаемые изменения.

### S05 — повторное использование устаревшего смещения и гонка записи — P1

**Причина:** `ModifyParameter` берёт `offset` из прежнего `info_.parameters`, затем заново
читает файл и пишет по старому адресу. Если игра, синхронизация или другой процесс
пересохранили данные, проверка размера не обнаруживает смену структуры. Нет проверки
исходного хеша, идентичности сессии или исключительного доступа.

**Исправление:** API записи возвращает явный отказ до файловых операций; UI его не вызывает.

**Остаточный риск:** механизмы разрешённой сессии, блокировки и обнаружения внешних
изменений ещё не реализованы. Проверки наличия игрового процесса одной недостаточно.

### S06 — разрушительный fallback и непроверенный результат записи — P1

**Причина:** после неудачного `std::filesystem::rename` строки 284–296 открывают целевой
файл с `trunc`. В Windows замена существующего файла через rename может завершиться
ошибкой. Результаты `write`, `flush` и закрытия не проверяются полноценно; повторный
эвристический `Load` не подтверждает сохранность всего графа данных.

**Исправление:** удалены временная запись, прямое усечение и этот fallback. Тест проверяет
неизменность исходных байтов и отсутствие создаваемого `.tmp` при отклонённой операции.

**Остаточный риск:** атомарный writer с проверкой результата, устойчивостью к сбоям и
сохранением метаданных ещё отсутствует. Его реализация сама по себе не исправит схему.

### S07 — неподтверждённая резервная копия и небезопасное восстановление — P1

**Причина:** `.bak` создаётся только при отсутствии файла и не связывается с игроком,
сборкой или ревизией. `RestoreBackup` напрямую перезаписывает активный файл; наличие
`.bak` ошибочно представлено как достаточное условие обратимости операции.

**Исправление:** восстановление отклоняется без изменения диска. Наличие соседнего `.bak`
показывается только как метаданные. Регрессия проверяет сохранность и исходника, и копии.

**Остаточный риск:** не установлены происхождение, целостность и актуальность старых копий.
Отчёт не рекомендует восстанавливать их автоматически или удалять.

### S08 — произвольный выбор активного игрока — P2

**Причина:** `Discover` выбирает первый файл с девятибайтовым префиксом; порядок обхода
каталога не определяет активный аккаунт. Расширение `.tmp` не исключено, `.bak`/`.log`
проверяются с учётом регистра; имя файла выдаётся как подтверждённый Player ID.

**Исправление:** несколько кандидатов дают отказ без выбора; `.bak`, `.tmp`, `.log`
исключаются без учёта регистра, файловые symlink пропускаются. Отображается путь кандидата,
не подтверждённая личность игрока. Читаются 17 байт ожидаемого заголовка.

**Остаточный риск:** заголовок не доказывает принадлежность Slutopia. Текущий фиксированный
префикс также может пропустить допустимый иной NRBF-заголовок. Выбор профиля не реализован.

### S09 — неограниченное чтение и неполное сбрасывание состояния — P2

**Причина:** файл целиком читается через `istreambuf_iterator` без верхнего лимита;
часть ошибок файловой системы игнорируется. При неудачном открытии `valid` очищается,
но старые параметры и метаданные могут остаться в `info_`.

**Исправление:** до нового обхода состояние очищается; исключения discovery превращаются
в сообщения об ошибке. Обход ограничен 512 записями каталога; кандидаты больше 16 MiB
отклоняются, из подходящего файла читается только заголовок. Добавлены тесты усечения,
замены, отсутствия, неоднозначности и превышения размера.

**Остаточный риск:** лимиты не являются таймаутом I/O. Недоступный отдельный файл может
быть пропущен с общим результатом «нет кандидата»; отдельная классификация всех причин
отказа чтения и отдельный тест лимита 512 пока отсутствуют.

### S10 — пути Unicode и расположение LocalLow — P2

**Причина:** пути сохранений и копий преобразуются через `.string()`; результат зависит
от кодировки Windows и может потерять символы или вызвать исключение. Путь LocalLow
собирается вручную из профиля пользователя, а не из соответствующей known folder.

**Исправление:** путь основы берётся через `FOLDERID_LocalAppDataLow`, пути остаются
`std::filesystem::path`, UI/лог получают UTF-8. Удалена сборка путей writer через узкие
строки. Есть регрессия с каталогом `сохранения`.

**Остаточный риск:** длинные пути и все варианты перенаправления профиля отдельно не
проверены. Имя компании/продукта остаётся сообщённым кандидатом; это не поиск всех профилей.

## 3. GameDetector

Исходники: [Gemini .cpp](https://github.com/bloxcrusher/SlutopiaTrainer/blob/4903c5c79e75f23df956c1faacaaaa6dc8d64d70/src/core/GameDetector.cpp),
[Gemini .hpp](https://github.com/bloxcrusher/SlutopiaTrainer/blob/4903c5c79e75f23df956c1faacaaaa6dc8d64d70/src/core/GameDetector.hpp).
Исправление: [GameDetector.cpp](../src/core/GameDetector.cpp).

### G01 — неверный каталог Steam-манифеста — P2

**Причина:** два вызова `parent_path()` от EXE дают `steamapps/common`, тогда как
`appmanifest_4612690.acf` лежит в `steamapps`. Соответственно, build ID обычно теряется.

**Исправление:** отсчёт ведётся от каталога игры с подъёмом ещё на два уровня;
`InspectExecutable` отдельно тестируется на искусственной структуре Steam.

**Остаточный риск:** это поддержка ожидаемого расположения EXE непосредственно в
`common/<installdir>`, не произвольной вложенности или любой пользовательской установки.

### G02 — неподтверждённая идентичность и build ID — P2

**Причина:** наличие пути или процесса `Slutopia.exe` трактуется как обнаруженная игра;
из манифеста читается только первый похожий `buildid`, без проверки app ID и каталога.

**Исправление:** кандидат должен быть обычным файлом с нужным именем; в манифесте
проверяются `appid`, `installdir`, числовой build ID и отсутствие дубликатов выбранных
полей. Неоднозначные/несоответствующие данные оставляют `Unknown` и ошибку. UI явно
называет установку кандидатом по имени.

**Остаточный риск:** EXE не проверяется по хешу/подписи и может быть посторонним файлом.
Regex для метаданных не является полноценным Valve KeyValues-парсером. Build ID не
включает адаптер. Сравнение `installdir` сейчас чувствительно к регистру.

### G03 — выдуманные версия движка и архитектура — P2

**Причина:** имена Unity/Mono-модулей превращаются в «Unity 6000.0 / x64», а
`productVersion` без чтения присваивается `6000.0.60f1`. Те же значения повторены в UI.

**Исправление:** модули подтверждают только наблюдение соответствующих библиотек.
Версия EXE читается из ресурса; неизвестная версия продукта/движка остаётся `Unknown`.
Архитектура процесса берётся из существующего `IsWow64Process2`, не из имени модуля.

**Остаточный риск:** версия EXE не обязана быть версией Unity; отдельное определение
точной версии Unity и проверка оригинальности модулей не реализованы.

### G04 — неполный поиск Steam и непроверенный тип реестра — P2

**Причина:** несколько жёстких путей и `MAX_PATH`-буфер не охватывают пользовательские
библиотеки; `RegQueryValueExW` не проверяет тип значения. Чтения `libraryfolders.vdf` нет.

**Исправление:** `RegGetValueW` ограничен строковым типом и большим проверяемым буфером;
добавлено чтение современных записей `path` в `libraryfolders.vdf`. Результаты файлового
чтения ограничены 256 KiB; стандартные пути остаются дополнительными кандидатами.

**Остаточный риск:** старые формы VDF, экранирование всех видов и все конфигурации Steam
не покрыты. Детектор по-прежнему предполагает папку `Slutopia`; чтение реального реестра
и пользовательских библиотек не входит в детерминированный интеграционный тест.

### G05 — недостаточная защита чтения version resource — P2

**Причина:** выделяется размер ресурса без собственного лимита; перед использованием
`VS_FIXEDFILEINFO` не проверяются длина структуры и её сигнатура.

**Исправление:** лимит 1 MiB, проверка результатов API, размера структуры и
`dwSignature`; при несоответствии возвращается `Unknown`.

**Остаточный риск:** это защита чтения метаданных, а не проверка целостности PE.
Специальный корпус повреждённых version resources в тесты не включён.

## 4. TrainerManager

Исходник: [версия Gemini](https://github.com/bloxcrusher/SlutopiaTrainer/blob/4903c5c79e75f23df956c1faacaaaa6dc8d64d70/src/core/TrainerManager.cpp).
Исправление: [TrainerManager.cpp](../src/core/TrainerManager.cpp).

### T01 — перезапись предпочтения auto-connect — P2

**Причина:** при пустом целевом EXE обнаруженная установка принудительно устанавливает
`settings.autoConnect = true`, даже если настройка была выключена.

**Исправление:** можно заполнить только пустое имя цели; предпочтение автоподключения
сохраняется. Интеграционный тест подтверждает сохранение пользовательской цели и `false`.

**Остаточный риск:** тест с отключённым discovery не воспроизводит отдельно весь случай
«пустая цель + обнаруженная реальная установка». Удаление принудительного присваивания
подтверждено также чтением кода; полная матрица требует внедряемого discovery.

### T02 — ложное сообщение о подтверждённых параметрах — P2

**Причина:** успешный эвристический `Load` логируется как `verified parameters`,
а ошибки инспекции остаются преимущественно в логе.

**Исправление:** `RefreshSave` передаёт сообщение в `notice` и журнал без утверждения
о доверенных игровых значениях. `Load` не сообщает успех схемы по одному заголовку.

**Остаточный риск:** `notice` — общее поле для разных операций; следующая операция может
перезаписать предыдущее уведомление. Полноценной очереди диагностик по подсистемам нет.

### T03 — smoke-тест затрагивает реальные данные профиля — P2

**Причина:** конструктор всегда обнаруживает установку и читает локальные сохранения,
включая запуск GUI smoke. Даже при отдельном каталоге JSON это не изолирует игровые пути.

**Исправление:** параметр `inspectInstallation = false` выключает discovery и инспекцию
сохранений при smoke/интеграционном запуске; `main` передаёт его для `--smoke-gui`.

**Остаточный риск:** это изоляция конструктора, не песочница. Тест не должен вручную
вызывать реальное discovery/refresh. В обычном GUI эти действия по-прежнему синхронные.

## 5. UserInterface

Исходник: [версия Gemini](https://github.com/bloxcrusher/SlutopiaTrainer/blob/4903c5c79e75f23df956c1faacaaaa6dc8d64d70/src/ui/UserInterface.cpp).
Исправление: [UserInterface.cpp](../src/ui/UserInterface.cpp).

### U01 — ссылки инвалидируются при успешной записи — P1

**Причина:** цикл держит `const auto& p` из `info.parameters`. Кнопка вызывает
`ModifyParameter -> Load`, который заменяет вектор. Затем UI снова читает `p.displayName`,
`p.id` или `p.note` и продолжает итерацию. Это обращение к инвалидированным объектам.

**Исправление:** редактирующие циклы удалены; UI показывает только метаданные кандидата
и отключённые функции с причинами.

**Остаточный риск:** для будущего редактора нужны стабильные ID и отдельная модель команд;
перезагрузку нельзя выполнять внутри обхода изменяемого контейнера. GUI smoke не является
автоматическим воспроизведением старого сценария use-after-invalidation.

### U02 — ошибки быстрых кнопок теряются — P2

**Причина:** `+100`, `+1000`, `+10000`, `+1 Level` и `+5 Levels` игнорируют возвращаемый
результат и текст ошибки `ModifyParameter`; пользователь не знает, применилось ли действие.

**Исправление:** эти неподтверждённые действия удалены; доступная инспекция выводит
сообщение `RefreshSave` и пишет его в журнал.

**Остаточный риск:** новые изменяющие команды должны иметь один общий путь обработки
результата и отображать подтверждение только после независимой верификации результата.

### U03 — арифметическое переполнение и отсутствие диапазонов — P2

**Причина:** прибавление к `int32`/`int` выполняется без проверки верхней границы;
ручной ввод допускает отрицательные/семантически недопустимые значения. Переполнение
знакового типа в C++ — неопределённое поведение.

**Исправление:** операции прибавления и ручная запись отключены вместе с редактором.

**Остаточный риск:** допустимые диапазоны, единицы и связанные инварианты для реальной
игры не установлены; будущая UI-проверка не заменяет проверку в адаптере.

### U04 — устаревшие edit-кэши — P2

**Причина:** статические `unordered_map` индексируются только ID параметра и не
сбрасываются после reload, восстановления или смены профиля. Поле ввода может содержать
значение от другой ревизии/игрока.

**Исправление:** неподтверждённые edit-кэши удалены.

**Остаточный риск:** будущая модель правок должна включать идентичность профиля,
ревизию данных и явное разрешение конфликта с внешней записью.

### U05 — ложные гарантии и пути в неверной кодировке — P2

**Причина:** интерфейс пишет «Confirmed Local Currencies», «Restorable» и фиксированные
Unity/Mono/x64, хотя этих гарантий код не устанавливает. `.string()` для пути установки
может не соответствовать UTF-8, ожидаемому ImGui.

**Исправление:** показаны кандидат по имени, наблюдаемые модули, неизвестные сведения,
недоступность восстановления и причина отключённых функций; пути UI передаются в UTF-8.

**Остаточный риск:** ручная оценка шрифтов, DPI, длинных путей и удобства на разных
Windows-системах ещё нужна. Smoke проверяет жизнеспособность отрисовки, а не все тексты
и клики. В SETTINGS после discovery ещё нет отдельной полной модели асинхронного статуса.

## 6. Сборка, тесты и совместимость

### C01 — нарушена переносимая сборка — P2

**Причина:** Gemini без условия добавил `ProcessInspector`, `GameDetector`, Windows-заголовки
и библиотеки в `trainer_common`. Linux-конфигурация CMake успешна, но сборка падает на
`ShlObj.h` раньше доступных переносимых тестов.

**Исправление:** Windows-исходники и библиотеки подключаются под `WIN32`; Win32-часть
`SaveManager` условная. Common tests снова собираются GCC.

**Остаточный риск:** Linux-сборка проверяет только переносимые компоненты. Сам GUI остаётся
Windows-only; MinGW/ARM64/x86-сборки в этой проверке не заявляются.

### C02 — тесты подтверждали эвристику вместо контракта — P2

**Причина:** искусственный буфер содержит ровно ожидаемые старым сканером байты, а
проверка `engine` требует лишь непустую строку, которая уже задана константой. Нет
доказательства NRBF-схемы, безопасной записи или правильного определения реальной игры.

**Исправление:** вместо ложного подтверждения добавлены отрицательные регрессии,
проверки неизменности файлов и детерминированные Windows integration tests для
манифеста, неизвестной версии и изоляции `TrainerManager`.

**Остаточный риск:** нет положительных тестов игровых сохранений, fault injection
файлового writer, сетевой синхронизации или сценариев кликов редактора: самого
поддерживаемого редактора пока нет.

## 7. Реализованные функции и неподтверждённые возможности

### Работает на уровне приложения и диагностики

- Отдельное Win32/DX11/ImGui-приложение с RESOURCES, PROGRESSION, MISC, SETTINGS.
- Поиск процесса, PID, путь, архитектура, модули, статус, фоновое переподключение и
  очистка после завершения процесса; RAII для process handles.
- Кандидаты установки, наблюдаемая версия файла, проверяемые поля Steam-манифеста;
  поиск современных Steam library paths без гарантии поддержки всех форматов.
- Метаданные NRBF-header кандидата: путь, размер, наличие соседнего `.bak`.
  Ни активный игрок, ни параметры этим не подтверждаются.
- JSON-настройки, сохранение предпочтений, лог, F5/F6, CLI и metadata collector.
- Явный отказ от неподтверждённых изменений; видимые причины недоступности функций.

### Игровые функции, которые не реализованы как подтверждённые

| Возможность из ветки Gemini / плана | Статус после исправления |
| --- | --- |
| Soft, Hard, GirlCrystal, Star, StandardTickets, Contracts, BP, Jewel, Smiles | Имена ключей сообщены Gemini; значения не читаются как доверенные и не редактируются |
| `PlayerLeveler` / `rewardedLevel` | Не подтверждён как отображаемый уровень; извлечение и запись отключены |
| Локальные ресурсы/счётчики | Нет проверенного адаптера или значений |
| Таймеры и скорость офлайн-процессов | Не реализованы; единицы и границы не установлены |
| Локальный прогресс и гарантированное сохранение правок | Не подтверждены ни для одной реальной сборки |
| Резервирование и восстановление игрового save | Метаданные `.bak` доступны; создание/восстановление редактором отключено |
| Energy и серверное слияние валют | Есть сообщённые Gemini выводы; независимой проверки в этой среде нет; редактирование не поддерживается |
| Покупки, платные разблокировки, серверные проверки и аутентификация | Вне допустимых функций проекта; обход не реализуется |

Обычный JSON-файл **настроек трейнера** сохраняется. Это отдельный механизм
`ConfigManager`, не доказательство возможности сохранять игровые параметры.

## 8. Почему запись отключена и условия безопасного восстановления

Улучшения только файлового writer недостаточно: можно атомарно записать неверные байты
в правильный файл. Нужны одновременно доказательство схемы, локальной принадлежности
параметра и безопасная транзакция. Наличие `.bak` также не делает исходную операцию
безопасной, если не определены её происхождение и корректный способ восстановления.

### Этап A — воспроизводимые исходные данные

1. Зафиксировать Steam app/build ID, SHA-256 EXE и `Assembly-CSharp.dll`, версию движка
   и backend. Полная игра и demo — разные профили совместимости.
2. Предоставить обезличенные описания типов/членов `SavedData`, `Memento` и конкретного
   обычного локального параметра, включая связанные поля, единицы и ограничения.
3. Подготовить приватные резервные копии и обезличенные фикстуры A/B после одной
   легитимной игровой операции; сохранить наблюдаемые значения и хеши. Нужны варианты
   с другим порядком объектов/ID, пустыми/неизвестными полями и изменением версии схемы.
4. Установить, кто управляет параметром. Локальное кэширование и работа без сети сами
   по себе не доказывают авторитетность клиента. Премиальные права и серверные значения
   не выбирать для эксперимента и не поддерживать как обход проверок.

### Этап B — валидируемый адаптер чтения

1. Реализовать bounded NRBF-reader без выполнения сериализованного кода и без
   небезопасного вызова BinaryFormatter на неизвестных данных.
2. Разрешать тип/член через схему и ссылки графа, проверять длины, арифметику, типы,
   количество элементов, неизвестные записи, неоднозначность и целостность файла.
3. Привязать адаптер к подтверждённому профилю сборки. Неизвестная версия всегда
   должна оставлять функции отключёнными.
4. Сначала проверить только чтение по фикстурам и показаниям игры. Положительный
   результат чтения ещё не включает writer.

### Этап C — транзакция и резервные копии

1. Выбирать профиль явно; фиксировать исходный файл/ревизию/хеш и разрешённую сессию.
   Исключить гонки с игрой, Steam Cloud и другими процессами; перед commit проверять
   внешние изменения. Одного флага «игра закрыта» недостаточно для эксклюзивности.
2. Создавать проверяемую резервную копию до операции, не перезаписывать единственный
   известный хороший экземпляр. Хранить локально идентичность/версию/хеш без публикации
   приватных данных.
3. Сериализовать в отдельный файл того же тома; проверять каждый write/flush/close,
   заново валидировать результат и использовать подходящую Windows-операцию замены
   с определённой семантикой. Не возвращать fallback с `trunc`.
4. Спроектировать отдельное безопасное восстановление: проверка копии, текущей ревизии,
   исключительного доступа и сохранности текущего файла. Само наличие `.bak` не достаточно.
5. Добавить fault injection: read-only/locked target, недостаток места, частичная запись,
   ошибка replace, изменение файла другим процессом, авария до/после замены, неверная
   копия и попытка восстановления не того профиля.

### Этап D — UI и проверка на игре

1. Команды UI должны работать со стабильными ID и ревизиями, не со ссылками на элементы
   вектора, который может заменить backend. Любой результат проходит общий обработчик.
2. Проверять арифметику и диапазон в backend независимо от UI; сбрасывать/согласовывать
   кэш при reload, смене профиля и конфликте.
3. На точно указанной сборке проверить один обычный подтверждённо локальный параметр:
   чтение, легитимное изменение, повторную загрузку, закрытие/перезапуск и отсутствие
   повреждения другого прогресса. Проверить безопасный rollback.
4. Наблюдать разрешённую синхронизацию и конфликты, не обходя серверные проверки.
   Если значение серверное, оставить редактирование отключённым.

Возврат старого сканера, смена `valid = true`, включение кнопок или удаление сообщений
об отказе не являются выполнением этих условий.

## 9. Как продолжить работу

1. Взять `fix/antigravity-review` из PR #2; изучить этот отчёт и `AGENTS.md`.
2. Проверить текущий SHA и CI, поскольку приведённая выше доказательная база относится
   к конкретному коммиту исправлений.
3. Сначала собрать недостающие данные этапа A. Не коммитить игру, реальные сохранения,
   идентификаторы аккаунта, логи с токенами или полный memory dump.
4. Следующий программный шаг — тестируемый адаптер чтения и его фикстуры; writer остаётся
   отключённым до прохождения отдельных критериев B–D.

Windows-команды воспроизведения:

```powershell
cmake -S . -B build -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure --timeout 30
.\build\Release\SlutopiaTrainer.exe --list
.\build\Release\SlutopiaTrainer.exe --smoke-gui
```

Переносимые тесты:

```sh
cmake -S . -B build-review -G Ninja -DBUILD_TESTING=ON
cmake --build build-review
ctest --test-dir build-review --output-on-failure
cmake -S . -B build-sanitize -G Ninja -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer" \
  -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined"
cmake --build build-sanitize
ctest --test-dir build-sanitize --output-on-failure
```

Этот отчёт документирует проверку и исправления PR #2. Он не разрешает автоматически
сливать PR, менять `main` или перезаписывать ветку Gemini.
